# Sample Task-Management Domain

This is a fictional example domain for demonstrating QA workflows. The rules below are sample acceptance criteria, not claims about another product. For real work, use the target application's own requirements and source.

## Example model

- A project groups tasks.
- A task has a title, optional description, status (`todo`, `in_progress`, or `done`), priority (`low`, `medium`, or `high`), and optional due date.
- A user may create, view, update, and delete tasks in a project they can access.
